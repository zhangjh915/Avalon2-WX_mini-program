## 0. 资产清单与取图方式

### 走云存储，不进主包

本地文件在 `miniprogram/assets/ui/`，但已通过 `project.config.json` 的
`packOptions.ignore` **排除出包体**——和角色立绘、身份牌卡背同样处理。
本地那份只是上传中转。

原因：这批资产 1.11 MB，而主包上限 2 MB、代码本身才 274 KB。
全放进包里会占掉 72%，只剩 550 KB 给后续所有功能。排除之后主包是 **370 KB（18%）**。

**所以落地前必须先把 `miniprogram/assets/ui/` 整个目录上传到云存储**，
路径保持 `assets/ui/...` 不变（和 `assets/roles/`、`assets/cards/identity/` 同级）。

上传用 `scripts/upload-cloud-assets.js`（参数是相对 `miniprogram/` 的路径，
同时也就是云存储上的 cloudPath）：

```
node scripts/upload-cloud-assets.js assets/ui/floor-green.jpg assets/ui/floor-wine.jpg
```

两个坑：devtools 的 `cli cloud` 只有 `env` 和 `functions`，**没有 storage**，
所以上传只能在小程序上下文里调 `wx.cloud.uploadFile`，脚本走 automator 注入；
而 `uploadFile` 的 `filePath` **不认宿主机绝对路径**（报 `createUploadTask:fail
file not found`），必须先把文件 base64 搬进 `wx.env.USER_DATA_PATH` 再传。

`assets.js` 加一个取图函数，和现有的 `roleArt` / `identityBack` 同一个写法：

```js
// 界面图标与场景。和角色立绘一样走云存储，路径即 fileID 后缀。
function uiAsset(name) {
  return CLOUD_PREFIX + "assets/ui/" + name
}
```

下表「接到哪」里的路径都改用 `assets.uiAsset("xxx.png")` 取，
**不要写 `/assets/ui/xxx.png` 这种包内绝对路径**——排除出包后取不到。

wxss 里的 `background: url(...)` 同理不能用包内路径。三个办法：
（a）改成 `<image>` 节点，src 走 `uiAsset()`；
（b）在 js 里算好 fileID，用 `style="background-image:url({{...}})"` 内联；
（c）体积特别小、又是首屏关键路径的，单独留在包内。
桌子和地面建议走 (a) 或 (b)，见 §3、§4。

## 2. 任务指示器 `.mission-orb`（play.wxml:6）

四态**全部换成图片**，原来的圆形边框和背景色要一起去掉——四张图各自带完整的圆形外观。

```
待打    mission-pending.png     暗石板封印
当前轮  mission-current.png     点亮的金色封印
成功    crest-good.png          正义队徽（鹰翼环抱圣杯）
失败    crest-evil.png          邪恶队徽（蛇身盘环嵌宝石）
```

要删的 CSS（`play.wxss:98-145`）：`.mission-orb` 的 `border` / `border-radius` /
`background` / `color`，以及 `.mission-success` / `.mission-fail` / `.mission-current`
的底色和边框色。里面的 `.mission-symbol`（`{{item.label}}`）也不再需要。

**两条容易做错的：**

1. **队徽不要裁成圆、也不要外加圆框。** 正义那枚是桃形、邪恶那枚是圆环，
   这是设计本身，按原始轮廓直接摆。两枚长宽比是 0.89 / 0.95，排成一行不会高低不齐。
2. **底色不能再用绿/红。** 阵营色现在由队徽自己承载，绿徽压绿底会糊成一团。

> `mission-current.png` 是**接近旋转对称**的（旋转 15° 平均通道差 13.6），
> 可以用 CSS `animation: rotate` 表达「进行中」。`mission-pending.png` 旋转差只有 4.8，
> 转起来看不出来，不要给它加旋转。

## 3. 桌子

### 3.1 圆桌 `.round-table`（play.wxss:1271）

`table-round.jpg` **是带黑色四角的 JPEG**（存 JPEG 是为了从 472KB 降到 51KB）。

**必须保留 `border-radius: 50%`**，否则四角的黑块会露出来。

```css
.round-table {
  border: 0;                       /* 桌沿由图提供，删掉原来的 7rpx 描边 */
  border-radius: 50%;              /* 必须留，用来裁掉 JPEG 的黑四角 */
  overflow: hidden;
  /* 投影必须保留！桌面和地面都是正俯视平光，没有投影就完全没有深度线索，
     桌子会像一张贴纸浮在地毯上。实机验证过这一条。 */
  box-shadow: 0 14rpx 25rpx rgba(20, 14, 10, 0.45);
  /* 背景走云存储取不到包内路径，改成内联 background-image，或塞一个 <image> 铺满 */
}
```

> **只删 `border`，不要删 `box-shadow`。** 原来的投影是
> `0 14rpx 25rpx rgba(59,44,31,0.22)`，地面换成深色绒毯后要加深到上面那个值才看得出来。
> 长桌同理。

wxml 里内联（`roundTableBg` 在 js 里 = `assets.uiAsset("table-round.jpg")`）：

```html
<view class="round-table" style="background-image:url({{roundTableBg}})"></view>
```

### 3.2 长桌 `.long-table` —— 七张整图分档

**九宫格方案已废弃**，别再找那些切片了。它在实机上始终有可见接缝
（边条与中心的色差、角块与 `border-radius` 的配对），修了两轮仍不干净。
换成**七张不同比例的整桌图，按最近的比例挑一张**——一整张图，没有拼接，
也就没有接缝这一类问题。

`.long-table` 的长宽比不是几个预设，是 **29 个连续值**（`tableLayout.js:79-82`：
宽只看上下边人数、高只看左右边人数，两个参数独立，是笛卡尔积）。
竖向布局用横图转 90°，否则要 58 张。七张覆盖 29 个值，**最大拉伸 ±8.0%**，
绝大多数在 1–5%，木纹和包边上肉眼看不出来。

**七张的角部造型完全统一**（都是流畅的四分之一圆弧，不是方角配圆润角饰）。

| 档 | 比例 | 像素 |
|---|---|---|
| `1.png` | 1.09 | 563×517 |
| `2.png` | 1.28 | 578×452 |
| `3.png` | 1.54 | 630×408 |
| `4.png` | 1.82 | 683×375 |
| `5.png` | 2.13 | 736×345 |
| `6.png` | 2.45 | 751×306 |
| `7.png` | 2.90 | 915×315 |

比例元数据在 `assets/ui/table-long/_meta.json`，**别把上表的数字抄进代码**，读那个文件。

```js
// 长桌整图分档。竖向布局用横图转 90°，所以只存了长宽比 >= 1 的那一半。
// 注意：stage 的宽随屏宽变而高固定 590rpx，所以长宽比要用**运行时实测的
// stage 尺寸**算，不能写死——375pt 屏上 stage 是 1.19，414pt 屏上是 1.32，差 11%。
function pickLongTable(widthPct, heightPct, stageW, stageH) {
  const w = stageW * widthPct / 100, h = stageH * heightPct / 100
  const rotate = w < h
  const a = rotate ? h / w : w / h
  let best = LONG_TABLES[0]
  for (const t of LONG_TABLES) {
    if (Math.abs(Math.log(a / t.aspect)) < Math.abs(Math.log(a / best.aspect))) best = t
  }
  return { src: uiAsset(`table-long/${best.i}.png`), rotate }
}
```

```html
<image class="long-table" src="{{longTable.src}}" mode="scaleToFill"
       style="{{longTable.rotate ? 'transform:rotate(90deg)' : ''}}" />
```

**用 `mode="scaleToFill"`**，让图填满容器——那 ±7.4% 的拉伸就是这么吸收的。
用 `aspectFit` 会留边、`aspectFill` 会裁掉桌沿，都不对。

```css
.long-table {
  border: 0;
  border-radius: 0;                /* 圆角由图自带，别再裁 */
  box-shadow: 0 14rpx 25rpx rgba(20, 14, 10, 0.45);   /* 同 3.1，必须保留 */
}
```

> **为什么是 PNG 不是 JPEG**：桌角的雕花铜包角**伸出了圆角矩形之外**，
> 所以不能像圆桌那样用 `border-radius` 裁 JPEG——会把角饰切掉。实测验证过。
> 7 张合计 3.5 MB，但**玩家一局只下载其中 1 张**（对应他那间房的座位布局），
> 实际下载约 500 KB。

### 3.3 桌心纹章保持独立

`.table-emblem` 继续是绝对居中的独立节点，固定 `116rpx`，**不要烤进桌面图**——
长桌的比例是变的，烤进去的纹章会跟着 `cover` 浮动，极端比例还会被裁掉。

### 4.1 地毯四色可选

`floor-green` / `floor-indigo` / `floor-wine` / `floor-umber`，同规格只有颜色不同。

**建议做成个人偏好（本地 storage），不要做成房间级设置。** 理由：

- 它是**纯装饰**，不承载任何游戏信息，玩家之间看到不同颜色不影响对局
- 房间级要改房间数据结构和云函数（`missionSkin` / `roleSkin` 是那么做的，
  因为卡面必须全场一致）；个人偏好只要本地存一个 key，零服务端改动
- 玩家能随时换着玩，不用重开房

取图：`assets.uiAsset("floor-" + (floorColor || "indigo") + ".jpg")`。
默认值建议 `indigo`——四色里桌子和地面的明度差、冷暖差都最大，桌子最跳。

**连带必须改的一条：** 地面从浅灰换成深色绒毯后，
`.game-seat-token .seat-caption`（`play.wxss:1602`）的 `color: #343a36` 深色文字会消失在上面，
**要翻成浅色**（`#e6e2d8` 一档）。

### 结算页 `.verdict-mark`（result.wxml:4）

「光」/「影」两个字换成 `crest-good.png` / `crest-evil.png`，尺寸 `144rpx` 不变。

同时 `.good-verdict` / `.evil-verdict`（`result.wxss:6-7`）的绿/红渐变
**要改成中性深色渐变**——理由同 §2 第 2 条，阵营色现在由队徽承载。

## 5. 状态印 `seal-base.png`

9 个位置共用一张底：`.submitted-seal`（候/已/记/审/寂/杀，6 处）、
`.sigil-placeholder`（杯/封，2 处）、`.ceremony-mark`（夜，1 处）。

**汉字保留，叠在图上面。** 这些是抽象状态（等待中/已提交/已封存/沉寂/猎杀/首夜），
汉字对中文玩家零学习成本，图标化反而要学；而且每个印下面本来就紧跟一行标题文字。
换掉的只是原来那个「细金圈 + 粗体字」的 CSS 观感。

```css
.submitted-seal, .sigil-placeholder, .ceremony-mark {
  border: 0;                       /* 删掉原来的 3rpx 金圈 */
  background-position: center;
  background-size: contain;
  background-repeat: no-repeat;
  /* background-image 走云存储，在 js 里算好后内联，或改成一个铺满的 <image> 垫底 */
}
```

`.sigil-placeholder.sealed` / `.submitted-seal.spectator` 的灰化态，
可以继续用 `filter: grayscale(1)` 作用在同一张底上。

## 7. 验收提示

改完之后，**按逻辑点 × DPR 去看，不要按逻辑点看**（`750rpx = 屏宽`，
所以 `68rpx` 在 375pt 宽的屏上是 34pt，真机渲染成 `34 × DPR` 个物理像素）。
按逻辑点缩图验收等于模拟一台不存在的非 Retina 手机，比真机严苛一倍。

几个关键尺寸：座位角标 17pt、任务指示器 34pt、桌心纹章 58pt、胜负印 72pt。
