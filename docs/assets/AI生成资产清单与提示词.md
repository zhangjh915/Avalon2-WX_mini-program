## 0. 统一风格约定

所有提示词都默认追加这段风格后缀（下文各条不再重复写）：

```text
中世纪圆桌与羊皮纸档案风格，暗金、深木、烛火色调，克制的史诗感，
质感偏写实但不追求照片级，不要二次元，不要网游特效，不要现代元素，
不要文字，不要水印，画面干净、构图居中留白
```

**配色锚点**（取自当前界面，新资产要能和现有 UI 共存）：

| 用途 | 色值 |
|---|---|
| 背景底 | `#141c18` / `#1b2420` |
| 描边/分隔 | `#3d4a44` |
| 金（强调、皇冠、护身符） | `#c8aa62` / `#d8c27f` |
| 正义绿 | `#2f7358` / `#5aaa8c` |
| 邪恶红 | `#8b3f45` / `#c1656b` |

**通用技术要求**

- 图标类：`1:1`，在 `58rpx`（约 29px）下仍然可辨认。
- 卡牌类：`3:4`，实心背景，四角留 3% 安全边距。
- 背景类：`9:16`，主体偏上或偏下，**中间必须留出叠字空间**。
- 同一组资产用**一次组图请求**生成，风格才会统一（见下方生成方式）。

## 0.1 生成方式（doubao-seedream-4-0-250828）

接口：`POST https://openproxy-cn.zuoyebang.cc/openproxy/rp/v1/images/generations`

三条必须注意的：

| 项 | 说明 |
|---|---|
| `watermark` | **必须传 `false`**，默认示例里是 `true`，带水印的资产不能用 |
| 输出格式 | 返回 **JPEG，没有透明通道**。图标类需要透明背景的，只能生成后再抠图 |
| `size` | **必须写显式像素**（如 `1728x2304`）。传 `"2K"` 时比例由模型自己定，同一个 `"2K"` 可能返回 4:3 也可能返回 16:9 |
| 尺寸下限 | **总像素不得低于 3,686,400**（即 2560×1440，「2K」那一档）。低于此值报 `InvalidParameter: image size must be at least 3686400 pixels` |

推荐尺寸（均已满足下限）：

| 用途 | 比例 | size | 像素数 |
|---|---|---|---|
| 卡牌（任务牌、身份牌） | 3:4 | `1728x2304` | 398 万 |
| 图标（皇冠、护身符、火球） | 1:1 | `2048x2048` | 419 万 |
| 竖版背景（首页、终局、结算、首夜插画） | 9:16 | `1620x2880` | 467 万 |
| 圆桌俯视图 | 1:1 | `2048x2048` | 419 万 |
| 长桌俯视图 | 3:4 | `1728x2304` | 398 万 |

> 换其他比例时自己算一下：`宽 × 高 ≥ 3686400`。
> 例如 9:16 的 `1440x2560` 正好等于下限，可用但没有余量；`1620x2880` 更稳妥。
>
> 生成的图远大于实际显示尺寸（卡牌在界面上只有 104×154rpx），**下载后必须压缩**再进包。

**用组图保证同组风格一致**：设 `sequential_image_generation: "auto"` 并在
`sequential_image_generation_options.max_images` 指定张数，在**一个** prompt 里把这组
每张的内容依次描述清楚。建议分组：

| 组 | 张数 | 内容 |
|---|---|---|
| 任务牌 | 3 | 牌背 / 成功 / 失败 |
| 身份牌 | 3 | 牌背 / 正义底图 / 邪恶底图 |
| 道具图标 | 4 | 皇冠 / 护身符 / 破损护身符 / 魔法指示物 |
| 首夜插画 | 6 | 闭眼 / 邪恶相认 / 邪恶闭眼 / 单向提示 / 兰斯洛特 / 天亮 |
| 场景背景 | 5 | 首页 / 圆桌 / 长桌 / 终局 / 结算 |

> 破损护身符必须和完好版同角度同构图——放在同一组里生成正是为了这个。

> **图片 URL 24 小时后失效**，生成完立刻下载。

## 3. 首夜「天黑请闭眼」视频

这是唯一需要**动态资产**的地方。首夜由房主逐条推进（共 4–6 步，取决于本局角色），
每一步是一句主持词。建议做成**一段循环氛围视频 + 每步的静态插画**，而不是给每句话
单独做视频——首夜节奏由真人主持掌握，时长不固定。

### 3.1 循环氛围视频（必做）

| 项 | 说明 |
|---|---|
| 时长 | 8–12 秒，**首尾无缝循环** |
| 尺寸 | 9:16，建议 1080×1920 |
| 用途 | 首夜整个阶段作为背景持续播放 |
| 要求 | 不要有明显运动主体，避免喧宾夺主；亮度整体压低，保证白字可读 |

```text
提示词：
夜晚的中世纪石厅，画面中央一支蜡烛缓慢摇曳，烛光在石墙上投下轻微晃动的阴影，
空气中有极细的尘埃缓慢飘浮，画面四周沉入深黑，整体几乎静止，
只有火焰与尘埃在动，氛围神秘肃穆，无人物，无文字，
镜头完全固定不移动，首尾可无缝循环
```

### 3.2 各步骤静态插画（可选，做了更有仪式感）

首夜脚本由 `miniprogram/data/ttsLines.js` 的 `buildNightCeremonyFromSettings`
按本局角色动态拼装，步骤如下。每步配一张 9:16 插画即可。

| 步骤 | 主持词（节选） | 提示词 |
|---|---|---|
| 闭眼 | 夜幕降临。请所有骑士闭上眼睛，将手机扣在桌面上。 | `中世纪石厅长桌俯视，桌上整齐扣放着数块深色石板（象征扣下的手机），烛光昏暗，四周无人，寂静` |
| 邪恶方相认 | {角色}，请睁开眼睛。安静地确认与你共享黑暗的同伴。 | `黑暗中数双发着微弱红光的眼睛在对视，其余部分完全沉入黑色，只见轮廓，神秘、危险，无面部细节` |
| 邪恶方闭眼 | 黑暗中的共谋者，请闭上眼睛。 | `刚刚熄灭的红色微光，黑暗重新合拢，画面几乎全黑只余一丝暗红余烬` |
| 单向身份提示 | {角色}保持闭眼。所有单向身份关系已通过命运密令传递。 | `一封封蜡的信笺静静躺在石桌上，蜡印为金色圆桌纹章，烛光侧照，强调"信息已私下送达"` |
| 兰斯洛特相认 | 两位兰斯洛特，请同时睁开眼睛，确认彼此。 | `两把交叉的长剑，一把泛着银白圣光，一把泛着暗红微光，剑刃在中心交汇，对称构图` |

## 5. 生成后的落地清单

生成完成后按下面的路径放置（目录需要新建）：

```
miniprogram/assets/
  cards/       任务牌、身份牌（3:4）
  icons/       皇冠、护身符、破损护身符、魔法指示物（1:1 透明）
  scenes/      首页、圆桌、长桌、终局、结算背景（9:16 / 1:1）
  night/       首夜循环视频与各步骤插画
  roles/       角色头像（3:4）
```

**注意小程序包体积限制**：主包上限 2MB。图片务必压缩（建议 TinyPNG），
首夜视频体积较大，应放到**云存储**用 `wx.cloud` 拉取，不要打进包里。

替换时需要同步改动的位置：

| 资产 | 代码位置 |
|---|---|
| 任务牌 | `play.wxml` 的 `.mission-card-back` / `.mission-card-front` |
| 皇冠 / 护身符 / 火球 | `play.wxml` 中所有 `symbol-icon` 类的 emoji |
| 身份牌 | `play.wxml` 的 `.role-card`、`.role-art-placeholder` |
| 各类封印占位（候/已/记/封/密/夜） | `play.wxml` 的 `.submitted-seal`、`.ceremony-mark` |
| 桌面背景 | `room.wxml`、`play.wxml` 的座位容器 |
| 首夜视频 | `play.wxml` 的 `phase === 'night'` 区块 |
