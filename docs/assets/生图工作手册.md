> 最后更新：2026-08-17

## 1. 工作规则（必须遵守）

1. **每次发请求前，先跟用户确认要请求的提示词、模型、数量。** 不允许擅自批量跑。
   用户已明确授权的批量范围除外（例如"这版按 2 模型 × 3 张抽卡"）。
2. **API key 绝不写进仓库内任何文件，也不要直接打在命令行里。** 本仓库会推到公开的 GitHub。
   key 存在仓库外的 `~/.avalon-llm-key`（权限 600），每次用时 source 进来：
   ```bash
   source ~/.avalon-llm-key
   ```
3. 生图产物目录 `docs/assets/generated/` 已在 `.gitignore` 中，不入库。
   最终选定的资产放 `miniprogram/assets/` 并提交。
4. **图片 URL 24 小时后失效**，生成后必须立即下载存盘（脚本已自动处理）。

## 2. 接口与脚本

### 2.1 接口

```
POST https://openproxy-cn.zuoyebang.cc/openproxy/rp/v1/images/generations
Header: Authorization: Bearer $LLM_API_KEY
```

可用模型：

| 简称 | 模型 ID | 说明 |
|---|---|---|
| `5` | `doubao-seedream-5-0-260128` | 支持组图 |
| `5pro` | `doubao-seedream-5-0-pro-260628` | **质感更好，但不支持组图** |
| `4` | `doubao-seedream-4-0-250828` | 旧版，已不用 |

### 2.2 四个必须注意的接口约束

| 项 | 说明 |
|---|---|
| `watermark` | **必须传 `false`**。官方示例默认 `true`，带水印的资产不能用 |
| 输出格式 | 返回 **JPEG，没有透明通道**。需要透明背景的图标只能生成后再抠图 |
| `size` | **必须写显式像素**。传 `"2K"` 时比例由模型自定，同一个 `"2K"` 可能返回 4:3 也可能 16:9 |
| 尺寸下限 | **总像素 ≥ 3,686,400**（即 2560×1440）。低于此值报 `InvalidParameter: image size must be at least 3686400 pixels` |

**`5pro` 不支持 `sequential_image_generation` 参数**——连传 `"disabled"` 都会报
`InvalidParameter`。非组图时必须**整个字段省略**。这也意味着**组图模式在 pro 上不可用**，
需要成套一致的资产（牌背/成功/失败）只能靠提示词约束逐张生成，或退回用 `5`。

### 2.3 「成套一致」怎么做：组图这条路走不通

成功/失败牌要和牌背成套，27 个角色插画彼此要一致——直觉是用组图
（`sequential_image_generation`，一次出一组风格统一的图）。**但这条路在本项目走不通**，
三个理由叠在一起：

1. **`5pro` 根本不支持组图**（见 2.2）。而两张定稿牌背都是 `5pro` 出的，
   材质明显强于 `5`。
2. **组图只能一次性出一整组，没法把已有的图纳进来。** 牌背已经定稿，
   用组图重出一套等于推翻定稿。
3. 退回用 `5` 出组图的话，整套资产的质感要降一档，而且和已定稿的两张牌背对不上。

**所以成套一致只能靠提示词对齐**：把 6.0 的风格基准段原样复用，
每张只换主体描述那一两句。这也是 6.0 那样组织文档的原因。

> **待探**：接口是否支持**图生图 / 参考图**（给 `5pro` 传一张定稿图当风格参考）。
> 如果支持，成功/失败牌、身份牌、27 个角色插画的一致性问题一次解决，
> 比提示词对齐可靠得多。之前没试过，值得花 1–2 次请求探明。

### 2.4 生图尺寸（均已满足下限）

| 比例 | size | 像素数 | 用途 |
|---|---|---|---|
| 3:4 | `1728x2304` | 398 万 | 卡牌（任务牌、身份牌） |
| 1:1 | `2048x2048` | 419 万 | 图标、圆桌俯视图 |
| 9:16 | `1620x2880` | 467 万 | 竖版背景、首夜插画 |

换其他比例自己算：`宽 × 高 ≥ 3686400`。9:16 的 `1440x2560` 正好等于下限，能用但无余量。

### 2.5 脚本

Key 存在仓库外的 `~/.avalon-llm-key`（权限 600），每次 `source` 进来，
不要写进任何仓库内文件、也不要直接打在命令行里：

```bash
source ~/.avalon-llm-key

# 抽卡（默认）：发 N 次独立单图请求，得到同一提示词的 N 个不同方案
DIR=<子目录> ./scripts/gen-image.sh <模型ID> <标签> <尺寸> <张数> "<提示词>"

# 例：
DIR=任务牌背/A-扁平烫金 ./scripts/gen-image.sh \
  doubao-seedream-5-0-pro-260628 cardback-A 1728x2304 3 "……"

# 成套组图（仅 5 可用）：一次生成一组内容关联、风格统一的图
GROUP=1 ./scripts/gen-image.sh doubao-seedream-5-0-260128 cardset 1728x2304 3 "……"
```

产物落在 `docs/assets/generated/$DIR/`，命名 `{标签}_{模型简称}_{序号}.jpeg`。
`DIR` 省略时落在 `generated/` 根目录——**不要省**，几十张图堆在一起没法挑。

**注意**：抽卡模式的"张数"是**独立采样次数**，不是组图。选风格阶段要的是独立采样
（同一提示词的不同方案），组图给出的是"一组内容关联的图"，用途不同。

### 2.6 对比图脚本

抽完必须拼对比图再挑，不要一张张点开看：

```bash
# --actual 传的是界面上的逻辑尺寸（pt），不是物理像素
python3 scripts/make-contact.py <目录或图片…> --out <输出前缀> --actual 52x77
```

一次产出两张，各回答一个不同的问题：

| 输出 | 回答什么 |
|---|---|
| `{前缀}_全尺寸.png` | 这版风格对不对——质感、构图、有没有白角 |
| `{前缀}_真实尺寸.png` | **验收看这张**：真机物理像素下还认不认得出 |

真实尺寸图会铺界面底色 `#141c18`（在白底上看深色卡面会严重高估可辨认性），
并按 `逻辑尺寸 × DPR` 渲染成真机实际点亮的物理像素，默认同时出 @2x 和 @3x 两档，
**渲染完不做任何放大**（`--dpr` 可改）。

> 早期版本干过「先缩到逻辑尺寸、再用最近邻放大 2 倍方便看」，那是**错的**——
> 既模拟了一台不存在的非 Retina 手机，又凭空造出真机上没有的块状模糊，
> 把本来能用的资产判死过一次。详见第 5 节「踩过的坑」。

### 2.7 产物目录结构

docs/assets/generated/

## 3. 尺寸标准：按资产实际显示大小定风格

**这是整个生图工作最重要的一条经验。** 不能用统一标准，各资产在界面上差别极大：

| 资产 | 实际显示（逻辑点） | 该用什么风格 |
|---|---|---|
| **身份牌整卡** | **≈345 × 360 pt**（几乎满屏宽） | **可以很华丽**，玩家会盯着看 40 秒，细节全看得见 |
| 身份牌内插画位 | 84 × 106 pt | 中等，主体要清楚 |
| **任务牌** | **52 × 77 pt** | 必须极简，只靠明暗对比，细节全是浪费 |
| 仪式符号 | 66 × 66 pt | 接近剪影 |
| 顶部图标 | 29 × 29 pt | 纯剪影，无细节 |

身份牌比任务牌大近 **7 倍**。对照图见 `generated/任务牌背/_对比图/_size-compare.png`：
同样两张图，在身份牌尺度上华丽藤蔓清清楚楚，缩到任务牌尺寸后几乎分辨不出。

**验收必须按实际尺寸看，不能看放大图。** 放大图上精致的纹样，在指甲盖大小下就是噪点。

**但"实际尺寸"指的是物理像素，不是逻辑点。** 上表里的数字全是**逻辑点（pt）**，
来自 wxss 的 rpx 除以 2。真机会把每个逻辑点渲染成 DPR 个物理像素：

| 资产 | wxss | 逻辑点 | @2x 物理像素 | @3x 物理像素 |
|---|---|---|---|---|
| 任务牌 | `104x154rpx` | 52×77 | 104×154 | 156×231 |
| 身份牌内插画位 | `168x212rpx` | 84×106 | 168×212 | 252×318 |
| 身份牌整卡 | `min-height:720rpx` | ≈345×360 | ≈690×720 | ≈1035×1080 |

按逻辑点缩图去验收，等于模拟一台不存在的非 Retina 手机，会**比真机严苛一倍**，
把本来能用的资产判死。详见第 5 节「踩过的坑」。

## 4. 提示词方法论

### 4.1 统一风格后缀（所有提示词都带）

```text
暗金、深木、烛火色调，克制的史诗感，
不要二次元，不要网游特效，不要现代元素，不要文字，不要水印，画面干净
```

### 4.2 必禁清单（两个模型共同的"过度发挥"倾向，pro 更严重）

```text
严禁出现：白色边框、白色四角、圆角外框、相框、画框、桌面、蜡烛、手、
任何环境或背景物体、卡片投影、文字、水印
```

不写这一段，模型会把"卡牌"理解成"桌上一张卡牌的照片"，给你加相框、蜡烛、木桌。

### 4.3 三条硬规则

1. **显式写主体占画面比例**（如"占画面高度三分之二以上"）。不写的话模型倾向于
   把主体画小、把装饰画满。
2. **小尺寸资产：背景压暗，只让主体亮。** 这是可辨认性的关键，比任何细节都重要。
   大尺寸资产（身份牌）不受此限。
3. **每组多抽几张再挑。** 抽卡有波动，同一提示词第 2 张完美、第 3 张就可能白边回潮。

### 4.4 配色锚点（新资产要能和现有界面共存）

| 用途 | 色值 |
|---|---|
| 背景底 | `#141c18` / `#1b2420` |
| 描边/分隔 | `#3d4a44` |
| 金（强调、皇冠、护身符） | `#c8aa62` / `#d8c27f` |
| 正义绿 | `#2f7358` / `#5aaa8c` |
| 邪恶红 | `#8b3f45` / `#c1656b` |

**结论先写在前面：**

| 皮肤 | 定稿文件 | 圣杯占高 | @2x | @3x |

### 阶段小结（v1–v3）

- **模型选 `5pro`**：材质与细节明显强于 `5`，"过度发挥"已被禁止清单压住。
- v3 把背景压得太死，边框和纹样一起消失了；v2 纹样又太满。
  两者的折中催生了下面的 A/B 对照。
- **不要 `cardback-v2_5pro_3`**：全尺寸最漂亮，但四角有白色标记。

### A/B — 两条美术路线的对照实验

v3 的问题：藤蔓和边框一起被"压得极暗"这条约束干掉了，画面光秃秃；金杯是镜面高抛光，
偏亮偏现代。v2 的问题：藤蔓从四角蔓延到中部两侧，和圣杯争地盘，太满。

于是把两条候选路线各抽 3 张对照（`5pro`，`1728x2304`）：

- **A 扁平烫金** — 古籍烫金装帧。纯色底、烫金线描圣杯、无立体反光。
- **B 实物皮革** — v1_5_3 的构图逻辑（四角纹样 + 清晰内框 + 中央留空）
  套在 v2 的皮革实物质感上；金杯改哑光做旧、明确禁止镜面抛光。

**结论：两条路都成立，B 更耐缩，A 在真机分辨率下完全可用。**

| 文件 | 四角 | 底色 | 圣杯占高 | @2x | @3x | 评价 |
|---|---|---|---|---|---|---|
| `cardback-A_5pro_1` | 干净 | `#0c291b` | **38%** | 95 | 110 | ✓ 构图最克制精致，但圣杯是全场最小，未达提示词要求 |
| `cardback-A_5pro_2` | 干净 | `#0f2518` | 52% | **67** | **78** | ✗ 线描最细，A 里最不耐缩 |
| `cardback-A_5pro_3` | 干净 | `#0e2317` | 56% | 105 | 116 | ✓ A 里对比最强 |
| `cardback-B_5pro_1` | 干净 | `#18281d` | 51% | 112 | 117 | ✓✓ **无硬伤**，四边边框完整，上下留白 26%/23% 基本居中 |
| `cardback-B_5pro_2` | **白角** | `#1a2a1f` | 55% | 119 | 121 | 全尺寸最漂亮，但四角纯白，且裁不掉（见下） |
| `cardback-B_5pro_3` | 干净 | `#17241a` | — | 122 | 122 | △ 双耳奖杯不是圣杯，藤蔓偏满偏亮，顶部边框断 |

「圣杯占高」量的是中央 32% 宽竖条内、排除上下边框线后的主体纵向跨度。
提示词写的是「二分之一以上」，只有 `A_1` 没达到——它偏低的对比差就是这么来的。
肉眼看全尺寸图容易误判主体位置，**这个数要量不要猜**。

「对比差」= 缩到该分辨率后，中央圣杯区亮度的 95 分位减去边缘区平均亮度。

附带发现：A 的底色 `#0c291b`/`#0f2518` 比配色锚点 `#141c18` 更绿更饱和（R 通道只有 12，
B 路线是 24）。A 系资产后续要在提示词里补一句压住绿饱和度。

#### 踩过的坑：把逻辑点当成了物理像素

**第一轮 A/B 的验收是错的**，当时判了「A 全面低于 B、A 路线放弃」，理由是一组
52×77 下的对比差。两处错叠在一起：

1. **`52x77` 是逻辑点不是物理像素。** wxss 里 `.mission-result-card` 是
   `104rpx × 154rpx`，750rpx = 屏宽，所以在 375pt 宽的屏上是 **52×77 pt**。
   真机把这 52pt 渲染成 `52 × DPR` 个物理像素：DPR2 是 104，DPR3 是 156。
   按 52 去缩图等于模拟一台不存在的非 Retina 手机，**比真机严苛整整一倍**。
2. **缩完又用最近邻放大了 2 倍**「方便看」，凭空制造出真机上不存在的块状模糊。

改用真实物理像素重测后，A 的对比差从 54–85 抬到 @3x 的 78–116，
和 B 的 117–122 只差一档，**A 完全可用**。原先那句「A 完胜失败」作废。

由此得到的规则不是"扁平不行"，而是：

- **验收必须按 `逻辑尺寸 × DPR` 的物理像素渲染，且渲染完不许再放大。**
  `make-contact.py` 已按此重写，默认同时出 @2x 和 @3x 两档。
- 主体是**实心色块**比**空心线描**更耐缩（A_2 的细线描是全场最差的 78），
  但只要真机分辨率够，线描风格并不出局。

#### 白角裁不掉

`cardback-B_5pro_2` 的白角全在最外 2.5%（43px）以内，按 3:4 裁掉 4% 后确实清零了
（见 `cardback-B_5pro_2裁角.jpeg`），但**顺带把上下两条金边框也裁没了**，
只剩左右两条，画面失去封闭感。裁角这条路不划算，白角只能靠重抽解决。

miniprogram/assets/
  cards/    任务牌、身份牌
