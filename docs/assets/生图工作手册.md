# 《圆桌秘闻》生图工作手册

> 最后更新：2026-08-17
>
> 这份文档是**图片/视频资产生产的唯一入口**，自成体系——只看这一份就能接着干，
> 不需要了解小程序代码。目标是为微信小程序《圆桌秘闻》（配合《亚瑟传奇》实体卡牌的
> 线下辅助工具）生产全部视觉资产。

## 1. 工作规则（必须遵守）

1. **每次发请求前，先跟用户确认要请求的提示词、模型、数量。** 不允许擅自批量跑。
   用户已明确授权的批量范围除外（例如"这版按 2 模型 × 3 张抽卡"）。
2. **API key 只从环境变量读，绝不写进任何文件。** 本仓库会推到公开的 GitHub。
   ```bash
   export LLM_API_KEY="……"   # key 找用户要
   ```
3. 生图产物目录 `docs/assets/generated/` 已在 `.gitignore` 中，不入库。
   最终选定的资产放 `miniprogram/assets/` 并提交。
4. **图片 URL 24 小时后失效**，生成后必须立即下载存盘（脚本已自动处理）。

## 2. 接口与脚本

### 2.1 接口

```
POST https://openproxy-cn.zuoyebang.cc/openproxy/rp/v1/images/generations
Header: Authorization: Bearer $LLM_API_KEY
```

可用模型：

| 简称 | 模型 ID | 说明 |
|---|---|---|
| `5` | `doubao-seedream-5-0-260128` | 支持组图 |
| `5pro` | `doubao-seedream-5-0-pro-260628` | **质感更好，但不支持组图** |
| `4` | `doubao-seedream-4-0-250828` | 旧版，已不用 |

### 2.2 四个必须注意的接口约束

| 项 | 说明 |
|---|---|
| `watermark` | **必须传 `false`**。官方示例默认 `true`，带水印的资产不能用 |
| 输出格式 | 返回 **JPEG，没有透明通道**。需要透明背景的图标只能生成后再抠图 |
| `size` | **必须写显式像素**。传 `"2K"` 时比例由模型自定，同一个 `"2K"` 可能返回 4:3 也可能 16:9 |
| 尺寸下限 | **总像素 ≥ 3,686,400**（即 2560×1440）。低于此值报 `InvalidParameter: image size must be at least 3686400 pixels` |

**`5pro` 不支持 `sequential_image_generation` 参数**——连传 `"disabled"` 都会报
`InvalidParameter`。非组图时必须**整个字段省略**。这也意味着**组图模式在 pro 上不可用**，
需要成套一致的资产（牌背/成功/失败）只能靠提示词约束逐张生成，或退回用 `5`。

### 2.3 生图尺寸（均已满足下限）

| 比例 | size | 像素数 | 用途 |
|---|---|---|---|
| 3:4 | `1728x2304` | 398 万 | 卡牌（任务牌、身份牌） |
| 1:1 | `2048x2048` | 419 万 | 图标、圆桌俯视图 |
| 9:16 | `1620x2880` | 467 万 | 竖版背景、首夜插画 |

换其他比例自己算：`宽 × 高 ≥ 3686400`。9:16 的 `1440x2560` 正好等于下限，能用但无余量。

### 2.4 脚本

```bash
export LLM_API_KEY="……"

# 抽卡（默认）：发 N 次独立单图请求，得到同一提示词的 N 个不同方案
./scripts/gen-image.sh <模型ID> <标签> <尺寸> <张数> "<提示词>"

# 例：
./scripts/gen-image.sh doubao-seedream-5-0-pro-260628 cardback-v4 1728x2304 3 "……"

# 成套组图（仅 5 可用）：一次生成一组内容关联、风格统一的图
GROUP=1 ./scripts/gen-image.sh doubao-seedream-5-0-260128 cardset 1728x2304 3 "……"
```

产物落在 `docs/assets/generated/`，命名 `{标签}_{模型简称}_{序号}.jpeg`。

**注意**：抽卡模式的"张数"是**独立采样次数**，不是组图。选风格阶段要的是独立采样
（同一提示词的不同方案），组图给出的是"一组内容关联的图"，用途不同。

## 3. 尺寸标准：按资产实际显示大小定风格

**这是整个生图工作最重要的一条经验。** 不能用统一标准，各资产在界面上差别极大：

| 资产 | 实际显示 | 该用什么风格 |
|---|---|---|
| **身份牌整卡** | **≈375 × 360+ px**（几乎满屏宽） | **可以很华丽**，玩家会盯着看 40 秒，细节全看得见 |
| 身份牌内插画位 | 84 × 106 px | 中等，主体要清楚 |
| **任务牌** | **52 × 77 px** | 必须极简，只靠明暗对比，细节全是浪费 |
| 仪式符号 | 66 × 66 px | 接近剪影 |
| 顶部图标 | 29 × 29 px | 纯剪影，无细节 |

身份牌比任务牌大近 **7 倍**。对照图见 `generated/_size-compare.png`：同样两张图，
在身份牌尺度上华丽藤蔓清清楚楚，缩到任务牌尺寸后几乎分辨不出。

**验收必须按实际尺寸看，不能看放大图。** 放大图上精致的纹样，在 52px 下就是噪点。

## 4. 提示词方法论

### 4.1 统一风格后缀（所有提示词都带）

```text
暗金、深木、烛火色调，克制的史诗感，
不要二次元，不要网游特效，不要现代元素，不要文字，不要水印，画面干净
```

### 4.2 必禁清单（两个模型共同的"过度发挥"倾向，pro 更严重）

```text
严禁出现：白色边框、白色四角、圆角外框、相框、画框、桌面、蜡烛、手、
任何环境或背景物体、卡片投影、文字、水印
```

不写这一段，模型会把"卡牌"理解成"桌上一张卡牌的照片"，给你加相框、蜡烛、木桌。

### 4.3 三条硬规则

1. **显式写主体占画面比例**（如"占画面高度三分之二以上"）。不写的话模型倾向于
   把主体画小、把装饰画满。
2. **小尺寸资产：背景压暗，只让主体亮。** 这是可辨认性的关键，比任何细节都重要。
   大尺寸资产（身份牌）不受此限。
3. **每组多抽几张再挑。** 抽卡有波动，同一提示词第 2 张完美、第 3 张就可能白边回潮。

### 4.4 配色锚点（新资产要能和现有界面共存）

| 用途 | 色值 |
|---|---|
| 背景底 | `#141c18` / `#1b2420` |
| 描边/分隔 | `#3d4a44` |
| 金（强调、皇冠、护身符） | `#c8aa62` / `#d8c27f` |
| 正义绿 | `#2f7358` / `#5aaa8c` |
| 邪恶红 | `#8b3f45` / `#c1656b` |

```
中世纪桌游任务卡牌的正面平视卡面设计图。深墨绿皮革压纹底色铺满整个画面，四边完全出血。

绝不与圣杯争夺视线。最外一道极细的暗金线边框。整体明暗层次分明：背景暗、主体亮，
确保缩小到指甲盖大小时仍能一眼认出圣杯轮廓。暗金、深木、烛火色调，克制的史诗感。
严禁出现：白色边框、白色四角、圆角外框、相框、画框、桌面、蜡烛、手、任何环境或背景物体、
卡片投影、文字、水印。不要二次元，不要网游特效
```

| 文件 | 评价 |
|---|---|
| `cardback-v3_5_1` | △ 背景压暗到位，圣杯偏小 |
| `cardback-v3_5_2` | △ 干净，但圣杯偏小、造型偏现代奖杯感 |
| `cardback-v3_5_3` | ✗ 背景叶片变高饱和绿，跳出色板 |
| `cardback-v3_5pro_1` | ✓✓✓ **推荐**。圣杯大而明亮，背景近全暗，小尺寸最清晰 |
| `cardback-v3_5pro_2` | ✗ 白边回潮 |
| `cardback-v3_5pro_3` | ✓✓✓ 次选。同上但杯身带宝石、更华丽 |

### 结论与推荐

- **模型选 `5pro`**：材质与细节明显强于 `5`，"过度发挥"已被禁止清单压住。
- **提示词用 v3**：决定性证据是真实尺寸对比，不是全尺寸观感。
- **首选 `cardback-v3_5pro_1`**（最干净；任务牌是一排 3-5 张同时出现，越干净越不糊）。
  次选 `cardback-v3_5pro_3`（更华丽）。
- **不要 `cardback-v2_5pro_3`**：全尺寸最漂亮，但四角有白色标记。

### 6.5 首夜「天黑请闭眼」（唯一需要动态资产）

首夜由房主逐条推进（4–6 步，取决于本局角色），每步一句主持词，时长由真人掌握。
所以做**一段循环氛围视频 + 每步静态插画**，而不是给每句话单独做视频。

**循环视频（必做）**：8–12 秒，9:16，**首尾无缝循环**，整体压暗保证白字可读。

```
夜晚的中世纪石厅，画面中央一支蜡烛缓慢摇曳，烛光在石墙上投下轻微晃动的阴影，
空气中有极细的尘埃缓慢飘浮，画面四周沉入深黑，整体几乎静止，只有火焰与尘埃在动，
氛围神秘肃穆，无人物，无文字，镜头完全固定不移动，首尾可无缝循环
```

**各步骤插画（可选）**，每张 `1620x2880`：

## 7. 定稿后怎么落地

选定的图放到（目录需新建）：

```
miniprogram/assets/
  cards/    任务牌、身份牌
  icons/    皇冠、护身符、破损护身符、魔法指示物
  scenes/   首页、圆桌、长桌、终局、结算背景
  night/    首夜循环视频与各步骤插画
  roles/    角色头像
```

**必须先压缩**：生成图是 1728×2304 约 1MB，而任务牌实际只显示 52×77px。
小程序主包上限 2MB，不压缩几张就爆。首夜视频体积大，应放**云存储**用 `wx.cloud`
拉取，不要打进包里。

替换资产需要改的代码位置（交给做代码的会话即可）：

| 资产 | 位置 |
|---|---|
| 任务牌 | `play.wxml` 的 `.mission-card-back` / `.mission-card-front` |
| 皇冠 / 护身符 / 火球 | `play.wxml` 中所有 `symbol-icon` 类的 emoji |
| 身份牌 | `play.wxml` 的 `.role-card`、`.role-art-placeholder` |
| 各类封印占位（候/已/记/封/密/夜） | `play.wxml` 的 `.submitted-seal`、`.ceremony-mark` |
| 桌面背景 | `room.wxml`、`play.wxml` 的座位容器 |
| 首夜视频 | `play.wxml` 的 `phase === 'night'` 区块 |

> **换任务牌图片之前**，要先让代码会话把翻牌动画从双面 3D 翻转改成两段 `scaleX`。
> 现在用的 `backface-visibility` 在微信渲染器里不可靠，换成图片后正反面叠加会比
> 文字占位更明显。
